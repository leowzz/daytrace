# 面向事件回溯的数据契约

## 最终目标

远端从采集数据回溯当时的大致状态，AI 总结任意时间段内的事件和上下文。压缩率与功耗优化服从可追溯性、语义召回与时间线完整性。

## 0.2.1 已实现

记录页新增「导出分析包（录音 + 时间线）」，暂停后导出全部已完成的本地录音：

```text
DayTrace-analysis-*.zip
├── manifest.json          时间索引、片段 ID、校验值、未知覆盖区间
├── audio/000000.opus      或旧录音 .wav
├── diagnostics.csv        原有采集诊断
├── capture-events.jsonl   新版结构化事件；旧历史可能为空
└── README.txt             远端读取约定
```

每段有 segment_id、session_id、音频路径/SHA-256、UTC 起止时间、采样时长、格式、VAD/码率。单独导出的 Opus 也有 `DAYTRACE_STARTED_AT_UTC_MS`、片段/会话编号等 OpusTags；旧 Opus 再导出时同样补入，不修改加密原件。旧 WAV 必须配合 manifest 使用。

时间来源为设备墙钟锚点加采样偏移，未做外部校准；毫秒字段精度不代表毫秒级实际误差。新 START 事件记录 run_id、墙钟/单调时钟锚点及 VAD 设置。事件的观察时间不等于音频精确发生时间。

当前没有 ASR 文本。manifest 明确标记 `transcript_status: not_transcribed`、`transcript: null`。

## 转写时间映射

远端 ASR 必须返回逐句起止 offset，有可靠支持时可提供逐词 offset。偏移以解码并完成 Opus pre-skip 处理后的音频为准：

```text
句子绝对开始时间 = 片段 start_at_utc_ms + 句子 start_offset_ms
句子绝对结束时间 = 片段 start_at_utc_ms + 句子 end_offset_ms
```

演示：片段在北京时间 14:03:20 开始，某句位于第 4.2–7.8 秒，则为 14:03:24.2–14:03:27.8。下一片段即使在 14:05 开始，也要使用它自己的锚点，不能顺接到 14:03:27.8。

必须校验 offset 在解码时长内。ASR 定位本身可能有误差，不能当成精密计时结果。

## 缺口与上下文

每个保留片段内部连续，不会删除内部静音再拼接。VAD 省略发生在片段之间。

分析包按导出音频的覆盖并集列出缺口，标记 `no_audio_in_export / cause: unknown`。原因可能是 VAD、短句丢弃、暂停、中断、删除或未采集。旧日志不足时不能补造原因；新采集/静音/恢复/删除日志仅提供线索。缺口不能写成“环境安静”或“没有事件”。首段前和末段后覆盖也未知。

30 秒是文件边界，不是事件边界。远端应按真实时间检索邻近片段，为目标窗口加载必要前后文，再按目标范围输出。

如果为 ASR 效率拼接音频，必须保存拼接偏移到每个源片段偏移的映射。逐句结果先映射回源片段，再生成现实时间；不能用拼接音频的时钟替代实际经过时间。

## 后续远端要求（尚未实现）

1. 导入：校验 schema、SHA-256、格式/时间范围，按 segment_id 幂等。
2. ASR：保留逐句原文、offset、模型/版本、语言、可用置信信息和失败状态；说话人先用匿名标签，不擅自推断身份。
3. 时间索引：按绝对时间检索相交片段，保留会话/run/邻接关系与缺口。
4. 事件：时间范围、描述、上下文、证据（segment_id + 文字/音频偏移）、支持程度、不确定性。
5. 总结：区分直接证据与推断，不虚构声音没有支持的地点/身份/动作；“有人提到某事”不等于“某事已经发生”。
6. 回看：事件可跳到支持它的原文和音频位置。

建议事件字段：event_id、start_at_utc_ms、end_at_utc_ms、title、description、context、evidence[]、support_level、coverage_notes[]。这是后续协议，不是目前 app 已生成的内容。

## 优化取舍

当前 VAD 默认 400 ms 最小人声、300 ms 前置、600 ms 尾部、mode 2，可能漏掉很短的“好”“不行”或轻声。后续应优先评估这些语义损失，选择更保守的保留策略；本版未修改用户现有筛选设置。

评价至少包含：短回应召回、关键实体/数字可懂度、跨片段对话连贯性、逐句对齐、证据回溯、实际耗电和存储。不能只看过滤比例。VAD 无法恢复已丢弃的环境声；音频不支持的状态保留未知，不自动新增定位/屏幕采集。
