## 验证边界

用户选择「保留暂停状态，先交付」，因此未进行计划中的 3 分钟连续锁屏测试，也没有完成 2 小时/8 小时/24 小时稳定性测试。上述短时证据只能说明前台服务和锁屏录音链路已启动，不能证明全天不会中断。

尚未实测：长时间 Doze/ROM 清理、通话和麦克风争用、撤销权限、磁盘满、真机强杀恢复、实际功耗。尾部损坏恢复已做 JVM 自动化测试，但未在此设备上强杀验证。没有对 5%–10% 每日额外耗电目标作出结论。

## 复现长时间验证

1. 在可见应用内点击「继续录音」或「开始录音」，确认通知出现。
2. 锁屏；不点击通知中的暂停/停止。记录开始时电量与充电状态。
3. 在仓库根目录运行：

```powershell
.\scripts\monitor-recording.ps1 -Serial fa7b189f -Minutes 120
```

4. 脚本每分钟采集持续时长、中断次数、系统静音状态和屏幕状态；异常显式报错，不更改设备状态。
5. 结束后手动停止，导出首尾及跨分段 WAV，核对声音和时长。连续性的最终判断需要结合音频内容；服务存活或样本计数增长本身不足以排除系统返回静音。
6. 进行 8 小时功耗测量时应拔掉充电线、固定网络和环境；USB 充电期间的电量数据不能直接当作待机耗电结论。
